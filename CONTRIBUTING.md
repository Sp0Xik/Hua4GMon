# Как участвовать в проекте

Спасибо за интерес к Hua4GMon! Самый ценный вклад — **проверка на
реальных роутерах**: у разработчика нет всех моделей Huawei, и часть
функций ждёт подтверждения (список — в
[HARDWARE_VALIDATION.md](HARDWARE_VALIDATION.md)). Для отчёта есть
шаблон issue «Результат проверки на железе».

## Сообщить об ошибке

Откройте issue по шаблону «Сообщить об ошибке» и приложите диагностику
из программы (Windows: «Сеть» → «Сохранить диагностику»; Android:
«Сеть» → «Скопировать диагностику»). IMEI, IMSI, ICCID, номер и серийный
номер в ней замаскированы, MAC-адреса, IP и DNS скрыты.

Об уязвимостях — не в открытом issue: см. [SECURITY.md](SECURITY.md).

## Окружение разработчика

Нужен Python 3.11 или новее (Android-сборка использует 3.11).

```bash
git clone https://github.com/Sp0Xik/Hua4GMon
cd Hua4GMon
pip install -r requirements-dev.txt
python main.py --demo          # Windows-версия в тестовом режиме
```

Тесты Android-интерфейса дополнительно требуют `pip install kivy==2.3.0`.
В Linux без дисплея UI-тесты запускаются под Xvfb: `xvfb-run -a pytest`.

## Перед pull request

Все три проверки должны проходить — их же выполняет CI:

```bash
ruff check .
mypy
pytest
```

CI также проверяет покрытие `core/` (не ниже 90 %), собирает .exe и APK.

## Правила проекта

- **Логика — в `core/`**, в `main.py` (Tkinter) и `android_main.py` (Kivy)
  — только интерфейс. Изменение в `core/` сразу действует на обеих
  платформах; если функция добавляется только в один интерфейс, опишите
  в PR, почему.
- **huawei-lte-api импортирует только `core/router.py`.** Интерфейсы
  работают с `RouterSession` и `SessionWorker` (это проверяет тест).
- **Запись в роутер — по принципу «прочитай → измени → запиши →
  перечитай»** (см. `core/band_lock.py`). Никаких значений по умолчанию
  вместо непрочитанных настроек.
- **Строки интерфейса — на русском и через `t()`**, перевод на
  английский — в `core/i18n.py`. Тесты находят строки без перевода и
  лишние переводы. На Android используются только символы из шрифтов
  DejaVu Sans в `assets/` (цветные эмодзи там не отображаются).
- **Нет роутера для проверки — не повод откладывать.** Реализуйте
  лучший вариант, отделите его, пометьте в docstring
  `Hardware validation required`, покройте тестами логику без железа и
  добавьте пункт в [HARDWARE_VALIDATION.md](HARDWARE_VALIDATION.md) (тест
  проверяет, что каждая пометка там описана).
- **Версия — только в `core/__init__.py`** (`__version__`); buildozer,
  VERSIONINFO и CI берут её оттуда.
- **Зависимости закреплены** в `requirements*.txt` и продублированы в
  `buildozer.spec` для Android (совпадение проверяет тест). После
  обновления перегенерируйте `LICENSES/THIRD-PARTY-NOTICES.txt` (команда —
  в начале файла).
- **Стек Android-сборки закреплён намеренно**: Buildozer 1.5.0 +
  python-for-android v2024.01.21 + NDK 25b + Cython 0.29.36. Новые p4a
  переходят на Python 3.14, где ломается pyjnius. Обновление — только
  отдельным PR после зелёной еженедельной canary-сборки.
- Windows-версия распространяется **одним portable .exe** — без
  установщика и без zip-архива.
- Заметные изменения описывайте в [CHANGELOG.md](CHANGELOG.md), раздел
  `[Unreleased]`.

## Загрузка изменений через веб-интерфейс GitHub

Если вы правите файлы не через git, а через «Add file → Upload files»,
загружайте **все изменённые файлы одним коммитом** (можно перетащить
папки целиком — структура сохранится). Если загрузить `core/` и файл
интерфейса разными коммитами, промежуточный коммит не пройдёт CI:
интерфейс будет импортировать функцию, которой ещё нет в `core/`.
