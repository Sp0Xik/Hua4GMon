# Проверка на реальном оборудовании

Hua4GMon 1.4.0 разработан и проверен без физического роутера и телефона:
логика покрыта тестами на симуляторе модема и на поддельном HTTP-роутере,
с которым работает настоящая huawei-lte-api 2.0.1. Ниже — всё, что
зависит от конкретной прошивки или устройства и должно быть подтверждено
на железе. В коде такие места помечены комментарием
`Hardware validation required`; тест `tests/test_project.py` следит, чтобы
каждое из них было описано здесь.

**Как проверить и сообщить результат.** Подключитесь к роутеру, пройдите
пункт, затем сохраните диагностику (Windows: «Сеть» → «🧾 Сохранить
диагностику»; Android: «Сеть» → «🧾 Скопировать диагностику») и
приложите её к issue с моделью и версией прошивки. Личные номера в
диагностике уже замаскированы.

## Роутер: LTE

### 1. `detect_ca` — агрегация несущих
- **Модуль:** `core/rf.py`
- **Реализовано:** агрегация определяется по `monitoring/status →
  CurrentNetworkTypeEx`: `1011` — LTE+ (CA), `101` — LTE без CA. Если
  роутер сообщает «без CA», лишние номера из поля `band` отбрасываются.
  Без этого поля — по числу распознанных бэндов.
- **Проверить:** зафиксировать два бэнда, которые оператор агрегирует
  (например, B3 + B1), затем только один.
- **Ожидается:** в первом случае «Агрегация (CA): Активна» и технология
  «LTE+ (CA)», во втором — «Нет» и «LTE». Значение CurrentNetworkTypeEx
  видно в диагностике (`monitoring_status`).
- **Оборудование:** Huawei B636-336, B535-232, B818-263.

### 2. `verify` — запись Band Lock
- **Модуль:** `core/band_lock.py` (запись — `RouterSession.apply_plan`
  в `core/router.py`)
- **Реализовано:** перед записью читается `net/net-mode`; меняется
  только `LTEBand`, `NetworkBand` (2G/3G) сохраняется; режим сети —
  «только 4G» для LTE-модемов. После записи настройки перечитываются и
  сверяются. «Все бэнды (AUTO)» засчитывается, даже если прошивка
  сохраняет маску поддерживаемых бэндов вместо `7FFFFFFFFFFFFFFF`.
- **Проверить:** «Применить Band Lock» с одним бэндом → «Все бэнды
  (AUTO)» → «Вернуть как было». Сравнить с веб-интерфейсом роутера.
- **Ожидается:** после каждого шага — зелёное сообщение, строка «Сейчас
  на модеме» совпадает с веб-интерфейсом; настройки 2G/3G не изменились;
  «Вернуть как было» возвращает исходные настройки.
- **Оборудование:** B636-336, B535-232, E3372h.

### 3. `parse_supported_bands` — бэнды модема
- **Модуль:** `core/parsers.py`
- **Реализовано:** из `net/net-mode-list → LTEBandList` объединяются биты
  всех элементов (кроме «все бэнды») и номера из имён вида `LTE BC3`.
  Формат различается между прошивками: элемент на бэнд или группы.
- **Проверить:** экран «Сеть» — список бэндов для Band Lock.
- **Ожидается:** в списке ровно бэнды, которые поддерживает модем по
  спецификации; бэнды из эфира — первыми.
- **Оборудование:** B636-336, B535-232, E3372h, B818-263.

### 4. `reattach` — переподключение мобильной связи
- **Модуль:** `core/router.py` (`RouterSession.reattach`)
- **Реализовано:** `dialup/mobile-dataswitch` 0 → пауза 3 с → 1 (до трёх
  попыток включения). Если приложение закрыли в паузе, `close()` включает
  данные обратно.
- **Проверить:** «📶 Переподключить связь» во время мониторинга.
- **Ожидается:** интернет пропадает примерно на 5–10 секунд и
  возвращается; мобильные данные в веб-интерфейсе включены; модем может
  выбрать другую соту (событие смены соты на мониторе).
- **Оборудование:** B636-336, B535-232.

### 5. `read_antenna` — режим антенны
- **Модуль:** `core/router.py`
- **Реализовано:** по очереди `get_antenna_settings`, `antenna_type`,
  `antenna_status`, `antenna_set_type`; берётся первый ответ с кодом 0–3.
  Какой геттер ответил, пишется в лог (Windows: `--verbose`).
- **Проверить:** выбрать «Внешняя» → «Применить», затем переподключиться.
- **Ожидается:** сообщение «Тип антенны изменён», после переподключения
  в списке стоит «Внешняя».
- **Оборудование:** B636-336, B535-232, B315s-22.

### 6. `mimo_status` — потоки MIMO
- **Модуль:** `core/rf.py`
- **Реализовано:** по `cqi0` / `cqi1`: второй CQI равен 0 при нормальном
  первом — «1 поток»; разница ≥ 4 — «потоки неравны»; иначе «2 потока».
- **Проверить:** отсоединить кабель второго порта антенны, затем вернуть.
- **Ожидается:** «1 поток» и совет проверить второй кабель без кабеля;
  «2 потока» — с кабелем. Если модель не отдаёт `cqi1`, строка CQI
  показывает одно число без вывода.
- **Оборудование:** B636-336 с внешней MIMO-антенной.

### 7. `parse_pusch_power` — мощность передатчика
- **Модуль:** `core/parsers.py`
- **Реализовано:** число после `PPusch:` в поле `txpower`, иначе первое
  число строки. ≥ 20 dBm — «на пределе», ≥ 15 dBm — «повышенная».
- **Проверить:** «Состояние» → «Мощность передатчика» при слабом и
  сильном сигнале.
- **Ожидается:** значение совпадает с веб-интерфейсом; при слабом сигнале
  мощность растёт.
- **Оборудование:** B636-336, B535-232.

### 8. `probe_huawei` — автопоиск
- **Модуль:** `core/discovery.py`
- **Реализовано:** параллельный GET `/api/webserver/SesTokInfo` (или
  `/api/webserver/token`) без входа по типовым адресам; модель — из
  `/api/device/basic_information`.
- **Проверить:** «Найти роутер» с подключённым Wi-Fi роутера.
- **Ожидается:** в поле IP подставлен адрес роутера, показана модель.
- **Оборудование:** B636-336 (192.168.8.1), B315s-22 (192.168.1.1).

### 9. `probe_host` — белые списки
- **Модуль:** `core/whitelist.py`
- **Реализовано:** TCP и TLS-рукопожатие с SNI (сертификат не
  проверяется). «Доступен» = рукопожатие завершено; TCP без TLS — признак
  фильтрации по имени сайта.
- **Проверить:** на SIM оператора с включённым режимом белых списков и
  без него.
- **Ожидается:** с фильтрацией — «⚠ Вероятна фильтрация»; без —
  «Белые списки ВЫКЛЮЧЕНЫ».
- **Оборудование:** любой роутер, SIM операторов РФ.

## Роутер: 5G

### 10. `classify_rat` — 5G NSA / SA
- **Модуль:** `core/rf.py`
- **Реализовано:** есть NR-метрики и LTE-метрики — «5G NSA»; только
  NR — «5G SA». Коды CurrentNetworkTypeEx для 5G не используются: они
  различаются между прошивками.
- **Проверить:** 5G CPE в зоне 5G (NSA и, если есть, SA).
- **Ожидается:** строка вышки и «Технология» показывают 5G NSA / SA; при
  уходе в LTE — «LTE».
- **Оборудование:** 5G CPE Pro 2 (H122-373), 5G CPE Pro (H112-372),
  5G CPE 5 (H155-381).

### 11. `_NR_KEYS` — имена полей NR
- **Модуль:** `core/models.py`
- **Реализовано:** перебор вариантов `nrrsrp` / `nr_rsrp` / `NrRsrp`,
  `nrsinr`, `nrrsrq`, `nrearfcn`, `nrpci`, `nrdlbandwidth`, `nrcellid`.
- **Проверить:** в диагностике (`device_signal`) — какие NR-поля отдаёт
  модем.
- **Ожидается:** на вкладке «Вышка» строка «5G NR» с RSRP / SINR; в
  списке графиков появились `nr_sinr` и `nr_rsrp`. Если поля названы
  иначе — добавить имя в `_NR_KEYS`.
- **Оборудование:** 5G CPE (см. п. 10).

### 12. `modem_supports_5g` — режимы 5G
- **Модуль:** `core/band_lock.py`
- **Реализовано:** модем считается 5G, если в `net-mode-list →
  AccessList` есть код с `08`. Тогда Band Lock не переводит сеть в
  «только 4G» и не выключает 5G.
- **Проверить:** Band Lock на 5G CPE.
- **Ожидается:** в подтверждении нет строки «Режим сети будет «только
  4G»»; после записи 5G продолжает работать.
- **Оборудование:** 5G CPE (см. п. 10).

## Windows

### 13. `enable_dpi_awareness` — масштаб экрана
- **Модуль:** `main.py`
- **Реализовано:** System-DPI-aware до создания окна; размеры и отступы
  масштабируются по реальному DPI; переносы строк — по ширине окна.
- **Проверить:** масштаб 125 %, 150 %, 200 %; два монитора с разным
  масштабом; крышный режим (F11) на втором мониторе.
- **Ожидается:** текст чёткий, ничего не обрезано; крышный режим
  открывается на том мониторе, где окно.
- **Оборудование:** Windows 10 / 11, ноутбук 1920×1080 при 150 % и
  внешний монитор при 100 %.

## Android

### 14. `set_keep_screen_on` — экран во время мониторинга
- **Модуль:** `android_main.py`
- **Реализовано:** флаг окна `FLAG_KEEP_SCREEN_ON` при подключении,
  снятие при отключении. Разрешение `WAKE_LOCK` не нужно; в фоне флаг
  не действует.
- **Проверить:** оставить монитор на время дольше тайм-аута экрана; затем
  отключиться.
- **Ожидается:** во время мониторинга экран не гаснет; после отключения
  гаснет по обычному тайм-ауту.
- **Оборудование:** Android 11–16.

### 15. `ToneBeeper` — звук-парктроник
- **Модуль:** `android_main.py`
- **Реализовано:** `android.media.ToneGenerator` (громкость медиа);
  сигналы тем чаще, чем ближе значение к пику.
- **Проверить:** «🔊 Звук» и поворот антенны; свернуть приложение.
- **Ожидается:** сигналы слышны и учащаются у пика; в фоне звук
  прекращается.
- **Оборудование:** Android 11–16.

### 16. `_on_keyboard` — «Назад»
- **Модуль:** `android_main.py`
- **Реализовано:** «Инфо» / «Сеть» → монитор; на мониторе первое
  нажатие — подсказка, второе в течение 2 с — отключение; открытый
  диалог закрывается сам. targetSdk 33 — предиктивный жест не включён,
  приложение получает обычное событие «Назад».
- **Проверить:** кнопка и жест «Назад» на всех экранах.
- **Ожидается:** поведение как описано; приложение не закрывается
  случайно с монитора.
- **Оборудование:** Android 13–16 (жесты), Android 11 (кнопки).

### 17. `copy_diagnostics` — буфер обмена
- **Модуль:** `android_main.py`
- **Реализовано:** JSON диагностики копируется через `kivy.core.clipboard`.
- **Проверить:** «🧾 Скопировать диагностику» и вставить в мессенджер.
- **Ожидается:** вставляется полный JSON с замаскированными номерами.
- **Оборудование:** Android 12–16.

## Сборка и прочие проверки

18. **Подпись APK** (`.github/workflows/build-android.yml`). После
    добавления секретов `ANDROID_*` первая сборка должна показать в логе
    `apksigner verify --print-certs` сертификат вашего ключа. Следующая
    версия ставится поверх без удаления.
19. **Buildozer 1.6.0** (задача `canary`, раз в неделю). Если она
    зелёная несколько недель — можно переводить основную сборку на
    1.6.0 (тот же p4a v2024.01.21).
20. **Android 11–16** — установка APK, первый запуск, работа в
    портретной ориентации, поднятие клавиатуры над полем пароля
    (`softinput_mode = below_target`). targetSdk 33: принудительный
    edge-to-edge Android 15+ не включается.
21. **Перезагрузка роутера** (`SessionWorker`): реальный B636
    перезагружается 1–2 минуты. Ожидается: «Нет связи с роутером —
    переподключаюсь…», затем автоматическое подключение без действий
    пользователя.
22. **Граничные значения** (`extract_number`): при очень сильном или
    слабом сигнале часть прошивок отдаёт `>=-44dBm` / `<-140dBm`.
    Ожидается: число отображается, без «-».
23. **`rrc_status`, `month_statistics`**: поля есть не у всех моделей.
    Ожидается: если модель их не отдаёт — прочерк, без ошибок и без
    повторных запросов.
24. **CI на Windows**: UI-тесты Tk впервые запускаются на
    `windows-latest`. Ожидается: задача `build-windows` проходит шаг
    «Run pytest on Windows».
